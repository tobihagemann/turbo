# Claude Edition

This directory is the Claude Code edition of Turbo. The root [`CLAUDE.md`](../CLAUDE.md) covers project-wide context; this file adds edition-specific rules.

- Keep Claude Code tool vocabulary here: `TaskCreate`, `TaskList`, `AskUserQuestion`, the Skill tool, and Claude Agent tool phrasing are expected in this edition.
- This directory is the root of the `turbo` Claude Code plugin: skills under `skills/`, the mod under `hooks/` with its tests under `tests/` and its state contract under `types/`. Users install it from the marketplace at `../.claude-plugin/`.
- The mod never submits model-supplied text with `$.prompt.submit({ asUser: true })`. A model-controlled string in a bare user turn reads as the user's own authorization, so such a prompt goes out framed as the plugin's.
- A mod tool that runs a slash command for the model takes the identifier a user would type, such as a plan slug rather than a path, and validates it against a character class before building the command. The command then matches what the user would type, and the argument leaves no room for injected text.
- Claude peer review delegates to Codex. `/peer-review` is the stable abstraction (uses `/codex-exec` with a Turbo-controlled prompt). `/codex-exec` is the raw one-shot helper. `/consult-codex` is the consultation helper.
- Codex-specific changes belong under [`../codex/`](../codex/), not here.
- When changing a skill, convention, addition, plugin mod, or setup/update file here, mirror the change to the parallel file in [`../codex/`](../codex/). Translate vocabulary via [`../codex/docs/harness-vocabulary.md`](../codex/docs/harness-vocabulary.md). The two editions track each other behaviorally; vocabulary differs but principles stay aligned. Drift between editions is the most common failure mode. A capability one harness lacks is not drift: mirror the principle, never the other harness's ceiling. When a rule exists to work around a constraint only Codex has, this edition keeps the unconstrained form and the difference is recorded as an intentional divergence below. Narrowing a Claude gate, option set, or loop to match a Codex limit costs a real behavior and does not count as alignment.
- After mirroring, run [`/codex-exec`](skills/codex-exec/SKILL.md) to have Codex review the Codex sibling against `../codex/SKILL-CONVENTIONS.md` and `../codex/AGENTS.md`. Instruct it to read those conventions and the changed files and report findings directly, the way `/write-skill` reviews a skill, without invoking `$review-code` or any other skill. Review skills carry user-input gates that `codex exec` drops, stalling the run. Independent cross-edition eyes catch vocabulary leaks and behavioral drift the same-edition reviewer cannot see. Treat findings the same as a same-edition review (evaluate, apply).
- **Intentional divergence — crash retry:** `/codex-exec`'s retry-once-on-a-run-that-died-producing-nothing rule stays in this edition. Leave `$claude-print` without it: the evidence is codex-process-specific, and `$claude-print` Step 3 polls a shell session rather than observing a process, so a retry trigger there would license the premature give-up that Step 3 exists to prevent.
- **Intentional divergence — consultation option budget:** `AskUserQuestion` allows 4 options per question while Codex's `request_user_input` allows 3. Where a gate's concrete choices already fill the smaller budget, this edition adds the consultation option and the Codex edition displaces the option that fits least, routing the displaced one through "Other" with explicit freeform handling in the consuming step. `/apply-findings`, `/resolve-pr-feedback`, `/create-project-skills`, `/simplify-code`, and `/assess-technical-debt` differ from their Codex siblings for this reason; keep the asymmetry when resyncing. Both editions displace at `/update-dependencies`, whose strategies already fill either budget.
- **Intentional divergence — loop autonomy:** the Codex edition deliberately runs `$polish-code`/`$refine-plan` without this edition's iteration hard cap, skip/continue `AskUserQuestion` gates, and handoff-then-compact gate on a low-context signal, because Codex's `request_user_input` is unreliable in non-interactive modes. `/implement` Step 7 offers the same handoff-then-compact gate before QA, at a threshold of its own, and `$implement` omits that gate for the same reason. Keep the Claude gates as-is; do not strip them to match Codex when mirroring, and do not port Codex's autonomy here. The `/context-level` skill and the plugin mod's two gate tools stay out of `../codex/` too: the context tool that feeds the gate and the compact-and-continue tool it calls.
- **Intentional divergence — open items:** the plugin mod's open-items tool, the rule the mod injects for it, its `openItems` context block, `/resolve-open-items`, and the open-items `list` call in `/handoff` Step 2 stay out of `../codex/`, since Codex has no mod and no band above the prompt to list items in. Keep them here; do not add them to `../codex/` when resyncing.
- **Intentional divergence — clear and continue:** `/plan`'s plan mode ends Phase 6 by asking whether to clear the conversation and implement the plan, here or in a worktree, through the plugin mod's clear-and-continue tool. The tool also continues a cleared session from a handoff file. `/implement-plan` Step 1 enters a worktree with the EnterWorktree tool when asked to implement in one, and the plan-lane brief in `/implement-backlog`'s `references/parallel-split.md` asks for that. `$plan` keeps its halt message, and `$implement-plan` has no worktree input: Codex has no mod to clear and continue the session, and no EnterWorktree. Keep them here; do not add them to `../codex/` when resyncing.
- **Intentional divergence — memory consolidation:** `/dream` stays out of `../codex/`. It edits the Claude Code auto-memory directory in place. Codex reaches that directory only as the shared source `codex.sharedClaudeAutoMemory` enables, which a run of the Claude skill already covers, and Codex's own consolidated memory files stay read-only. Its `.turbo/` cleanup would work there, but stays with the memory pass as one skill. Keep it here; do not add it to `../codex/` when resyncing.
- **Intentional divergence — plan read projection:** `/implement-plan` Step 2 projects the share of the context window its read takes and, above 25%, asks whether to implement in this session or through one subagent per step. Its Step 3 passes the subagent answer to `/implement`, whose Step 3 then hands each Implementation Step to a fresh subagent briefed from `references/step-implementer.md`. `$implement-plan` reads every file without projecting or asking, and `$implement` has no subagent-per-step path: the projection needs the context reading that `/context-level` provides, which stays out of `../codex/`, and that question is what leads to the path. Keep both here; do not add them to `../codex/` when resyncing.
- **Intentional divergence — default-branch commit:** `/commit-staged` Step 2 and `/ship` Step 5 state that the current branch is kept and committed on, including when it is the default branch. The Codex siblings omit it. The sentence counteracts a Claude Code system-prompt rule ("If on the default branch, branch first") that Codex has no equivalent of, so it would be inert there. Keep it here; do not add it to `../codex/` when resyncing.
- **Intentional divergence — out-of-checkout writes:** `/backlog` Step 3 routes an append into another repo or the main checkout, `/self-improve` Step 6 a turbo lesson handoff into the Turbo checkout, `/handoff` Step 3 the handoff write, `/implement-plan` Step 4 the plan-status edit, and `/draft-plan` Step 6 a gated plan written into another repo through the Edit or Write tool, which the Bash sandbox does not gate. The Codex siblings leave those writes unqualified: `apply_patch` runs under the same sandbox policy as shell commands, so it offers no equivalent escape, and [`../codex/SKILL-CONVENTIONS.md`](../codex/SKILL-CONVENTIONS.md) bars a skill from requesting a wider sandbox for routine work. When Claude Code refuses a write to the main checkout from a session isolated to a linked worktree, `/backlog` prints the entry and `/implement-plan` names the edit for the user, and `/handoff` writes the handoff to the session scratchpad directory. Before attempting its edit from a linked worktree, `/implement-plan` Step 4 offers to leave the worktree with the ExitWorktree tool, as `/implement-backlog` Step 6 does. The Codex siblings omit those fallbacks, which depend on the tool routing, and the leave offer, which depends on ExitWorktree. Whether a denied cross-repo append fails silently under Codex, as it does here, and whether Codex refuses a main-checkout write from a linked worktree are unverified; establish that before adding a Codex-shaped rule.
- **Intentional divergence — parallel backlog split:** `/implement-backlog` takes a session listing and names parallel sets in Step 3, briefs extra sessions in Step 4 through `references/parallel-split.md`, starts at the lane when a working set and lane were passed in, and has every session prune its own entries in Step 6, after offering to leave its worktree with the ExitWorktree tool and removing the worktree once its commits are on the default branch or in a merged pull request. `$implement-backlog` has none of it and numbers its lane and prune steps 4 and 5. `codex queue` delivers a message to an open session, but under the Codex sandbox it fails to start its app server or to reach the daemon socket (probed on codex-cli 0.167.1), and [`../codex/SKILL-CONVENTIONS.md`](../codex/SKILL-CONVENTIONS.md) bars a skill from requesting a wider sandbox for routine work. Keep it here; re-run the probe before adding it to `../codex/`.
- **Intentional divergence — peer review execution:** `/peer-review` Step 3 runs a code review through `/codex-exec`'s scratch-workspace mode, where the repository stays read-only and the temporary directory is writable, so the peer can run test suites and mutation checks, and Step 2 tells it so. `$peer-review` stays limited to reading, and tells the reviewer so, to name the checks it could not run, and to mark a verdict resting on reading alone: `$claude-print` confines Claude through a tool allow-list of file reads and read-only git commands, which cannot express execution that leaves the repository unwritable. Whether Claude Code's own Bash sandbox could give `claude -p` that shape from inside the Codex sandbox is unprobed; probe it before adding execution to `../codex/`. Keep the execution here; do not narrow it to match when resyncing.
- **Intentional divergence — PR verdict record:** `/resolve-pr-feedback` Step 7 records every item's outcome, skip reasoning included, in the Step 13 task description once Steps 2 to 6 settle, and Step 8 adds its downgrades there, so Steps 8 through 13 read the record back after a compaction. `$resolve-pr-feedback` omits both: it keeps no goal or workflow file, and `update_plan` holds step labels and statuses but no description, so nothing it writes carries the record through a Codex compaction. Keep it here; do not add it to `../codex/` when resyncing.
- **Intentional divergence — PR landing:** `/land-pr` Step 4 offers handoff-then-compact on a low-context reading before resolving a round's feedback, and Step 8 leaves a merged pull request's worktree with the ExitWorktree tool, then removes it and deletes the local branch. Step 2 offers up to three reviewer candidates and Step 7 every merge method the repository allows. `$land-pr` has no context step and presents the commands that finish a worktree's cleanup from the main checkout, for the reasons the loop autonomy and out-of-checkout writes entries give. Under `request_user_input`'s three-option limit, it offers two reviewer candidates and two merge methods, taking the rest through a freeform answer. Keep them here; do not narrow them to match when resyncing.
- **Intentional divergence — sandbox-denial retry:** `/run-checks` and `/test-run-rules` re-run a command that failed on a sandbox denial with the Bash tool's `dangerouslyDisableSandbox` override before reporting it not run, failed, blocked, or inconclusive, and `/ship` Step 7 and `/split-and-ship` Step 2 re-run the upstream-tracking write a sandbox refused after a push. The Codex siblings omit them: [`../codex/SKILL-CONVENTIONS.md`](../codex/SKILL-CONVENTIONS.md) bars a skill from requesting a wider sandbox for routine work. Keep them here; do not add them to `../codex/` when resyncing.
